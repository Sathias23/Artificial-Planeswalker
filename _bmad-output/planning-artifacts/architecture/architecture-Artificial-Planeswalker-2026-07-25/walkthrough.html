Single-writer read model with a fire-and-forget relay

Two imperative shells over one shared core. The whole architecture is one property: state travels in exactly one direction, and nothing flows back.

Why this is the whole thing. "The agent drives, the app shows" is the product premise. Making it a structural fact rather than a UI convention is what stops it decaying — which is why AD-2 puts a CI-enforced boundary around the write path rather than trusting a review to catch it.

The three roles

The writer — src/mcp_server

FastMCP over stdio, spawned per session, stateless. The only process that mutates the database. After a mutation commits it tells the backend; it never waits on the answer.

The relay — src/companion/app

FastAPI, long-running, user-launched. Reads the same database, holds ephemeral display state — active deck, connections, tickets — and broadcasts pushes. Never writes.

The glass — the SPA

State from exactly two inputs: REST responses and WebSocket messages. Issues no writes at all. Every click is inspection or navigation.

Three processes

Hover any box. The two credentials are deliberately separated — the browser never holds the token that authorises pushing.

Two credentials that never touch. The agent token lives in the discovery file and authorises pushing. The WS ticket is single-use with a 30-second life and authorises receiving. If the browser ever held the agent token, an XSS would escalate from "can read the UI" to "can push arbitrary content into the session."

Cold-start reality

~12 MB, ~10 s

A cold 100-card Commander deck at Scryfall's compliant request rate. Stated so it is expected, not discovered — NFR-05 excludes first-fetch paint, so this is compliant.

One choke point

Pacing lives in the backend, never the UI, and is async throughout. Two rate limiters would jointly exceed the guidance; a blocking one would eat the 250 ms push budget.

Never a substitute image

Failures are signalled distinguishably so the client draws its own named placeholder — name, mana pips, type line. A generic grey card would make that unreachable.

How it splits

An epic owns a seam, not a layer. Everything touching the same decision lands in one epic — otherwise two epics eventually disagree about it.

The one serialisation worth respecting. contracts.py lands in E4 and is upstream of E5, E7's type imports, E8 and E9. Land the envelope early and change it rarely — the drift check means a late change ripples through a committed .d.ts and both mirrored bundles.

What the reviewer gate caught

Three lenses — technology currency, adversarial seam, good-spine rubric. Ten findings, all fixed in place before the spine was finalised.

Critical

A column that doesn't exist

The draft bound DFC face handling to cards.layout. There is no layout column. Now driven by the presence of per-face image_uris inside card_faces — which is the more precise signal anyway, since split/adventure/flip carry faces without per-face images and fall out automatically. No migration, no re-import. PRD FR-04 carries the same defect.

TypeScript 7 would break CI

TS 7.0 went stable 17 days ago. But typescript-eslint declined TS 7 support on day one and publishes a peer range of <6.1.0 — npm ci fails outright. NFR-07 requires eslint, so the asserted open floor would have broken the frontend gate on the first run. Pinned >=5.9,<6.1.
