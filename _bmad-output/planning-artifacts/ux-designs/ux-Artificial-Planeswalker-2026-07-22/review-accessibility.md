# Accessibility Review — Artificial-Planeswalker Companion

Reviewer: adversarial accessibility lens, BMad UX Reviewer Gate. Scope: DESIGN.md + EXPERIENCE.md as written, against their own declared floor (EXPERIENCE.md "Accessibility Floor", DESIGN.md "Contrast floors") and PRD FR-20 (reduced motion + baseline contrast; mouse-first posture accepted). All ratios below are computed WCAG 2.x relative-luminance contrast from the hex values in DESIGN.md frontmatter, not the prose claims.

## Overall verdict

The bones are better than most: the verified pairs mostly verify (text-primary 13.9–16.8:1, text-secondary 6.2–7.5:1, accent 8.6–10.3:1, focus ring specified globally, oracle text has a real-text path via Detail view, Esc layering is clean). But the spine's contrast floor is arithmetically self-refuting in one place — every sanctioned use of `text-muted` is 11px micro text, which can never qualify for the 3:1 "large text" escape hatch the restriction leans on — and the keyboard floor, as written, routes a keyboard user through 100+ tab stops of card tiles before they can touch the drawer the agent just pushed. A screen-reader user, meanwhile, gets zero signal for the product's own climax moment (the deck updating by itself). These are fixable at spec level now and expensive after implementation.

## Findings

- **critical** The `text-muted` restriction is vacuous and its sanctioned uses fail the spine's own floor. DESIGN.md admits `text-muted` is "below AA body contrast — large/incidental text only," but both sanctioned uses render in `{typography.micro}` (11px) — footer attribution (`text-muted` on `surface-base` = **3.32:1**) and timestamps. 11px/500 is not WCAG large text (large = ≥24px, or ≥18.66px bold); the floor in EXPERIENCE.md ("all body text ≥ 4.5:1; large text ≥ 3:1") therefore requires **4.5:1** for every place `text-muted` is actually permitted, and it hits at most 3.45:1 on any surface. The design system contains no legitimate `text-muted` use at all. Worse, the footer is the NFR-08 Scryfall attribution and WotC Fan Content Policy notice — legally load-bearing text for a public release, shipped below AA (DESIGN.md Colors + footer-attribution component; EXPERIENCE.md Accessibility Floor). *Fix:* either lighten `text-muted` to ≥ #8A8172-ish (≥4.5:1 on `surface-base`) or restate the floor honestly (e.g., footer runs `text-secondary` at reduced size; kill `text-muted` from type-bearing roles, keep it for disabled/decorative only).

- **high** Unknown-card truncated ID is `text-muted` micro on `surface-overlay` = **2.87:1** — below even the 3:1 large-text bar, and it is load-bearing: it is the *only* identifying information for an unknown card (the name slot literally says "Unknown card"). This directly violates DESIGN.md's own Don't ("`text-muted` for any load-bearing text") within DESIGN.md's own Card placeholder spec (DESIGN.md Components → Card placeholder). *Fix:* render the truncated ID in `text-secondary` (6.21:1 on overlay — passes).

- **high** Tier "A" chip fails AA: label chips are `{typography.heading}` = 17px/600, which is **not** large text (needs ≥18.66px bold), so the floor is 4.5:1. If the A chip keeps `label-foreground` (`text-inverse`) on `accent-dim`, that is **3.62:1** — fail. (S on `accent` = 9.48:1 passes; B/C as `text-secondary` on `surface-overlay` = 6.21:1 pass.) The spec never states the A chip's foreground, which is itself a defect (DESIGN.md Components → Tier row). *Fix:* specify A's foreground explicitly and make it pass — e.g., `text-inverse` on `accent` at reduced opacity is a trap; use `accent-bright` text on `surface-overlay` (10.8:1) with an `accent-dim` border, or bump the chip type to ≥19px/700.

- **high** The Tab order is a de-facto keyboard trap for the drawer. Declared order is "tiles → flip controls → drawer rows → pill → footer links": on a 100-card Commander deck that is 100+ stops (plus flip controls) between page focus and the Agent drawer's content, dismiss ×, and history strip — every time a push arrives. No skip link, no focus management on drawer open/close/content-replace is specified; a push that *replaces* drawer content in place will silently destroy focus if it was on a row. Also, the enumeration "tiles → flip controls" reads as two sequential groups (all tiles, then all flip controls), divorcing each flip control from its card; and the drawer ×, history chips, deck view toggle, and Detail-view close are absent from both the Tab enumeration and the Enter-activation list ("tile → Detail view, flip control → flip" is the entire list). This is not the arrow-key grid nav the PRD rejected — it is the declared floor failing its own "reachable and operable" bar (EXPERIENCE.md Interaction Primitives). *Fix:* (1) interleave each flip control immediately after its tile; (2) add a skip link ("Skip to agent panel") and/or move focus to the drawer header on open, returning it on close; (3) on in-place content replacement, move focus to the drawer header; (4) extend the Tab + Enter enumeration to *every* interactive element: drawer ×, history chips, view toggle, Detail × and flip, footer links.

- **high** Mana-curve stacked segments are color-only encoding with unusable adjacent contrast. Segment-vs-segment ratios: mana-blue/mana-red **1.03:1**, blue/colorless 1.13, black/green 1.07, green/colorless 1.07 — every non-white adjacent pair is under 1.3:1, and even white-vs-others tops out at 2.73:1. No separator, pattern, label, or text alternative is specified for the per-bucket color breakdown; only the total count above each bar is text (DESIGN.md Components → Mana curve bars; violates WCAG 1.4.1 use-of-color and the 3:1 non-text graphics floor). *Fix:* either declare the color breakdown decorative-only in the spec (counts are the data; add `aria-hidden` on segments and a text/tooltip breakdown in the bar's accessible name), or add 1px `surface-inset` separators between segments plus an accessible per-bar name ("3 cost: 5 cards — 3 green, 2 red"). Separators alone do not fix CVD ambiguity; the accessible name does.

- **high** The deck-change climax is invisible to assistive tech, and the "non-motion signal" is itself motion. aria-live is scoped to the pill and drawer header only; deck refetches explicitly "do not announce." The declared non-motion signals for a deck change are (a) a gold glow flash that fades over 200ms — a transient animation, not a non-motion signal, missable by anyone who glances away and non-existent for AT — and (b) a group-header count silently changing text. UJ-1's climax ("the deck view updates by itself within a second") therefore has no accessible signal at all (EXPERIENCE.md Accessibility Floor + Component Patterns → Quantity badge). *Fix:* keep refetch-level silence, but add one coalesced polite announcement per settled `deck_changed` ("Deck updated — Creatures 25") — the refetch-coalescing machinery already exists to debounce it; and stop calling the glow flash "the non-motion signal" — the count text is the non-motion signal, the flash is garnish.

- **medium** Reduced-motion coverage is a partial list posing as "every motion." The floor enumerates drawer slide, hover pop, image fade-in, curve bar animation, glow pulse — but the spines also specify: push-replace **crossfade** (200ms), **DFC flip** 3D Y-rotation, **Detail view** fade + 4px rise, and the refetch **header shimmer**; none has a stated fallback. Separately, the reconnecting pill's "gentle pulse" is a looping ambient animation — which DESIGN.md's own Don'ts column bans outright — and its reduced-motion state is unspecified (EXPERIENCE.md Accessibility Floor; DESIGN.md Do's and Don'ts). *Fix:* make the inventory exhaustive with a per-motion fallback table (crossfade → instant swap; flip → instant face swap; detail → instant appear; shimmer → static "updating" text or nothing; pulse → static caution dot, state already carried by dot-color + pill text). One blanket sentence will not survive implementation.

- **medium** Pill hover disclosure violates the spine's own ban. "Hover reveals the port and instance ID" — port/instance appear nowhere else in the UI, making this exactly the "hover-only disclosure of unique information" that Interaction Primitives bans, with no keyboard or screen-reader path specified (EXPERIENCE.md Component Patterns → Connection status pill vs. Interaction Primitives → Banned). *Fix:* make the pill focusable with the same disclosure on focus (tooltip pattern with `aria-describedby`), or print port/instance in the Disconnected state panel where it is actually needed.

- **medium** Zero semantic structure specified. Neither spine assigns a single ARIA role, landmark, or heading level: is the drawer a `complementary` region or a non-modal `dialog`? Is the Detail view `role="dialog" aria-modal="true"` (it must be — it has a scrim and Esc)? Are "CREATURES — 24" group headers headings? Is the deck grid a list? For a spec that calls itself "the behavior contract," the accessibility tree is entirely implementer's choice (EXPERIENCE.md Component Patterns, DESIGN.md Components). *Fix:* one short mapping table: deck name = h1; group headers = h2; drawer = `aside`/`region` labeled by push kind, its header a h2; Detail view = modal dialog labeled by card name; grid + drawer lists = `ul`; state panel = `region` with h2 headline.

- **medium** Detail view modal behavior is half-specified: open/close triggers exist, but no focus trap, no initial-focus target, and no focus-return-to-origin on close. Without a trap, Tab from inside the "modal" wanders into the 100-tile grid behind the scrim; without focus return, Esc dumps keyboard users at the document top (EXPERIENCE.md Component Patterns → Detail view). *Fix:* specify: focus moves to the dialog on open (close button or dialog itself), Tab cycles within it, close returns focus to the originating tile/row.

- **medium** Footer links are unidentifiable at rest: underline appears only on hover, and the surrounding text is the same `text-muted` — so at rest a link is distinguished by literally nothing (not even color), failing WCAG 1.4.1 and mouse-less discovery (DESIGN.md Components → Footer attribution). *Fix:* persistent underline (quiet is fine — underline in the same color reads calm), hover merely brightens to `text-secondary`.

- **low** Hit targets below WCAG 2.5.8's 24px minimum are likely for: session-history chips (micro 11px text chips, height unspecified), footer links (single 11px line), and the drawer/Detail × buttons (size unspecified). Only the DFC flip control declares a compliant target (≥32px) (DESIGN.md/EXPERIENCE.md component specs). *Fix:* declare ≥24×24px minimum interactive box (padding counts) for ×, history chips, and footer links in the spec, matching the flip-control precedent.

- **low** Thumbnail alt duplication: suggestion/swap/tier rows put the card name in visible text *and* alt = card name on the adjacent thumbnail, so screen readers hear every card twice per row (EXPERIENCE.md Accessibility Floor alt policy applied to rows). *Fix:* alt="" (decorative) on thumbnails whose row already names the card; keep the name-alt rule for grid tiles and Detail view where the image is the only carrier.

- **low** Unstated foreground colors invite drift: group headers ("CREATURES — 24", `label` 12px — not large, needs 4.5:1) and the Detail-view type line have no declared color. `text-secondary` passes everywhere (≥6.2:1); `text-muted` passes nowhere. Say which (DESIGN.md Typography/Components). *Fix:* declare `text-secondary` explicitly for both.

## Passes worth recording (so they don't get "fixed" into regressions)

- text-primary on all surfaces: 13.94–16.76:1. text-secondary: 6.21–7.47:1 (claim "≈6.7 on raised" verifies at 6.76). accent on base: 9.91:1 (claimed ≈8 — understated but passing). negative on raised 5.72:1, caution 6.66:1, positive 8.31:1 — all pass as text. text-inverse on accent (S chip): 9.48:1.
- Focus ring: accent on any surface ≥8.56:1, 2px/2px — comfortably above the 3:1 indicator floor.
- Pill states pair dot color with text — not color-only (verify the text names the state, not just the deck).
- Swap tints pair color with strikethrough + arrow + rule position — not color-only.
- Flip control visible at rest (0.65 opacity), not hover-revealed; hover pop confirmed presentation-only (reveals nothing).
- Esc layering (Detail first, then drawer) is unambiguous as written; single-level overlay stack helps.
- Detail view as the real-text path to oracle text is the right structural answer to art-as-content.
- Glow flash is single-shot and small; reconnect pulse "gentle" — no flash-frequency (2.3.1) risk on the face of the spec.
