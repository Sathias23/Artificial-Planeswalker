Session History — Home Options

Session history is a capped list of the last ~20 agent pushes this session — each labelled by kind and time — that lets you reopen earlier pushes, including older pushes of the same kind that the nav pills can no longer reach (pills only reopen the latest push per kind). The open decision: where does this list live? Two candidate homes are mocked below, in context. Both are faithful to current Voltglass surfaces; neither is recommended over the other here.

Option A — Extend the nav

A fifth "History" pill in the deck header opens an anchored popover listing all pushes chronologically, cross-kind.

What you gain

  • History is reachable without any agent view open — one click from the deck header at all times.
  • One global, chronological, cross-kind list: the whole session in a single place, newest first.
  • Sits beside the existing per-kind pills, so "latest per kind" and "everything" share one nav group.
  • The current agent-view modal is untouched — its header keeps its present layout.

What it costs

  • The popover is a NEW floating surface. The overlay stack is currently one level deep — the agent view is the only modal — so this needs a ruling.
  • A popover is not a modal, but it is new machinery: outside-click dismiss, Esc ordering against the modal, and focus handling all have to be defined.
  • Adds a fifth control to an already-populated header row (kicker + four pills + timestamps + unread dots).
  • Two overlapping affordances in one group: pills reopen latest-per-kind, the popover reopens anything — users must learn the split.

Option B — In-view header strip

A horizontal chip strip as a second header row inside the existing agent-view modal; clicking a chip swaps the view content in place (crossfade).

What you gain

  • No new surface — reuses the modal already ruled as the app's only overlay; the one-level overlay stack stays one level.
  • History sits where reopening happens: pick a chip, the view swaps in place with a crossfade — no open/close churn.
  • Deck header is untouched; the nav group keeps its current four pills.
  • Chips carry kind + time in the existing pill vocabulary — no new component language.

What it costs

  • History is reachable ONLY once a view is open — the first entry point stays the nav pills, so you must open something before you can go back further.
  • The strip competes for modal header space with title, count, and the Close pill.
  • In-place content swap must re-fire the view's focus/announce contract each time a chip is clicked.
  • Cross-kind chips inside a view titled by one kind may read oddly — a "Tier list" chip inside the Suggestions view swaps the whole view kind, not a tab within it.
