## Intent

**Problem:** `validate_deck` and the companion format check say "legal" or "pass" without saying which of the format's known rules they never looked at, so a 100-card Commander deck reads as fully checked when its size, commander and colour identity were not examined.

**Approach:** A hand-maintained per-format table in `src/logic/deck_validator.py` names the known rules not checked for each recognised format; both result models gain an `unchecked` list drawn from it, the companion format panel renders it, and the skills and tool descriptions say the same. No rule is enforced and no verdict changes.

**Decisions (Brad, 2026-11-10):** (1) `copy_exceptions` is listed for every recognised format, Standard included, so the verify line reads "a standard report lists nothing beyond rotation and copy exceptions"; (2) `validate_deck`'s `message` appends "Not checked: …" naming the rules when the list is non-empty; (3) the plan is kept whole over the 1600-token guideline (one goal; the epic requires artifacts, skills and `plugin/` in the same PR).

## Boundaries & Constraints

**Always:** reporting only — `is_legal`, `violations` and every row's status and detail stay byte-identical for every input; the table covers every member of `_KNOWN_FORMATS` (the recognised Scryfall keys; `FormatType` is `str | None` and has no members, so this is the closed set the verify line means); an unknown or empty format gets an empty list (its `unknown_format` violation and advisory rows already say what was skipped); entries follow a declared order; colour codes and wording follow existing conventions; companion stays read-only (AD-2).

**Never:** enforce or partially detect any listed rule (no oracle-text scan for copy exceptions, no 100-card check); change the six rows or `CHECK_ORDER`; hand-edit `openapi.json`, `types.d.ts`, `plugin/` or `static/`; touch `src/viewer/`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Commander | 100-card commander deck, `validate_deck` and route | `unchecked` names deck size, commander eligibility, colour identity, copy exceptions; verdict unchanged | none |
| Vintage | vintage deck | no restricted entry in `unchecked` | none |
| Standard | standard deck | `validate_deck`: rotation exposure and copy exceptions; route: copy exceptions only, rotation dropped, since its row already says it | none |
| Unknown / empty format | `potato`, `""` | `unchecked == []` | none |
| Gladiator | singleton, no commander | deck size, copy exceptions; no eligibility or colour identity | none |

## Implementation Notes

- **Shape.** `UncheckedRuleName` (declared order `deck_size`, `commander_eligibility`, `color_identity`, `rotation`, `copy_exceptions`, held in `UNCHECKED_ORDER`), `UncheckedRule{rule, detail}`, `UNCHECKED_RULES` written out one line per `_KNOWN_FORMATS` key, `_UNCHECKED_DETAIL` (one sentence per rule naming the format) and `UNCHECKED_PHRASES` (the `message` noun phrases). `validate_deck` fills `unchecked` via `_unchecked_for(format)` (`.get(format, ())`, so unknown and empty formats get `[]`); `format_check` copies it minus `rotation`. Both fields are required (no default).
