# Epic 16 Context: The Remaining Push Kinds

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Give the agent its full push vocabulary: proposed swaps as out/in card pairs, tier lists, and titled card groups with a paragraph of reasoning each — including cards the active deck doesn't run. The epic is deliberately cheap: the envelope, payload shapes, caps, and view-switching discipline were all settled in earlier epics, so this is three new MCP tools paired with three new views — no new seam and no contract change. Each story lands its tool and its view together, because a tool without its renderer would let a push arrive that the UI cannot display, breaking the "a push is never silently swallowed" rule mid-epic.

## Stories

- Story 16.1: Proposed swaps — tool and view
- Story 16.2: Tier lists — tool and view
- Story 16.3: Card groups — tool and view

## Requirements & Constraints

- Three MCP tools: `companion_show_swaps(payload)`, `companion_show_tier_list(payload)`, `companion_show_groups(payload)`. Each renders its kind in the agent panel; each new push replaces the panel's current content.
- Groups are distinct from suggestions: a group carries a title and a prose paragraph of reasoning over an arbitrary card set, including cards not in the active deck. Each kind gets its own tool — no generic `companion_display`.
- Tier vocabulary is the closed letter enum S/A/B/C/D; the free-text tier `name` carries the MTG meaning ("Auto-include", "Cut", …).
- Graceful degradation: tools never raise. On any failure they return a text result; on auth rejection they re-read the discovery file and retry exactly once.
- Payloads reference cards by Scryfall printing UUID only; the UI hydrates details and art through the existing REST endpoints. Unknown IDs degrade to the unknown-card placeholder while the row still renders its text.

## Technical Decisions

- **No contract change.** The `swaps`, `tier_list`, and `groups` payload shapes already exist in `contracts.py` (fixed when the envelope landed): `swaps` → `{out_card_id, in_card_id, rationale, out_qty, in_qty}`; `tier_list` → `{letter: Literal["S","A","B","C","D"], name, note?, card_ids[]}`; `groups` → `{title, rationale, card_ids[]}`. Optional agent-authored `title` on every payload. Caps (≤60 items/card IDs per list, ≤12 groups or tiers, rationale ≤600 chars, title ≤80, envelope ≤64 KB) are enforced at the endpoint; over-cap is rejected (413), never truncated; empty payloads are accepted and render the empty state.
- Tools are `async def`, post their envelope through the existing dependency-free leaf client (never importing `src.companion.app.*`), and return a compact text result carrying exactly one token from `displayed | app_not_running | no_clients_connected | payload_rejected | backend_error` plus the connected-client count — no payload echo, under ~200 tokens.
- The backend shape-validates and relays; it never reads the database on the push path, and card IDs are not validated at ingest.
- WebSocket `kind` is a closed enum already covering `swaps | tier_list | groups`; one discriminated union, one generated TS union, one switch. History orders by `ts`, never by `id`.
- TS types are generated by `openapi-typescript` from the backend's OpenAPI into a committed `.d.ts` with a CI drift check; card hydration goes through the single zustand card cache — no second data-fetching or state library.
- Built SPA is a committed artifact mirrored into `plugin/` by the existing rebuild + drift-check machinery; rebuild and commit both copies after UI changes.
- Standard tooling floors apply: mypy --strict, ruff line-length 100, Google docstrings, %-style lazy logging; eslint/prettier/vitest on the frontend.

## UX & Interaction Patterns

- **Swap row:** out/in tiles side by side joined by an accent arrow glyph on `surface-overlay`; "Out · N copies" tinted negative and "In · N copies" positive, in micro, above the tiles — tints on the labels only, never on the art. Rationale sits right of the pair in body `text-secondary`, with StatChips for price/curve/confidence beneath. An "in" card with 0 copies renders normally reading "0 copies".
- **Tier row:** 132px chip on the well surface, 44px tier letter with its name in micro `text-tertiary` beneath, then note and a thumbnail row. Letter colors ramp `accent-bright`(S) · `accent`(A) · `text-primary`(B) · `text-secondary`(C) · `text-tertiary`(D); the letter is always accompanied by its name in text so color never carries rank alone. Buckets render in payload order; empty buckets are skipped, not rendered as shells.
- **Group section:** title in heading type with numeric count in `text-tertiary`, rationale paragraph capped at ~900px measure, wrapped tile row. Tiles carry a quantity badge only when the card is in the active deck — "×0" would be a lie. Empty groups are skipped.
- All tiles and thumbnails follow the standard inspection contract (hover/focus sets the detail target, click pins). Thumbnails in rows that already name the card in text use `alt=""`.
- Nav pills are generic over the closed kind enum: each pill activates automatically on its kind's first push, carries an unread dot, and the existing view-switching rules (auto-open, in-place crossfade for same-kind, switch + unread mark for different-kind, dismissal never clears content) apply unchanged. With all four kinds shipped, the nav shows one pill per kind, quiet until its first push.
- Every spacing value from the token scale; radii and shadows through tokens; motion respects `prefers-reduced-motion` per the existing fallback inventory.

## Cross-Story Dependencies

- Depends on Epic 13 (agent channel, envelope, suggestions view, nav pills, view-switching rules) — all three stories extend that machinery without changing it.
- Story 12.1 fixed the payload shapes and caps the tools rely on; if a story finds itself editing `contracts.py`, that is a red flag against the epic's "no contract change" premise.
- The three stories are mutually independent; 16.3's final AC ("all four push kinds now exist, one pill per kind") is only fully observable once 16.1 and 16.2 have landed.
