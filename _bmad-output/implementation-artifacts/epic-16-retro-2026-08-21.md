### Diff-scope review (bmad-review: adversarial, edge-case-hunter, verification-gap)

All lens findings below were re-verified against primary sources before routing; unverified ones were dropped. Overlap between lenses is noted as signal.

**R1 — CONFIRMED (all three lenses + aggregate convergent): the whitespace-only card-id fix landed in one view of three.** Same fact as A3. GroupsView's `cardIdsOf` filters whitespace-only ids and its comment names the hazard ("commits `/api/card-image/%20`", GroupsView.tsx:124-141); SwapsView (:100, :163) and TierListView (:137, :180) guard only `cardId === ''`, so the same wire-legal input fires the dead request and mounts a permanently-dead tile there. No story session ever saw both sides — the 16.3 review patch fixed its own view only. **Disposition: fix now** (port the trimmed-non-empty filter; the [[greptile-catches-what-code-review-misses]] "fix one branch of N" class, third recurrence).

**R2 — CONFIRMED: the groups tool's agent-facing docstring misdescribes the render rule.** server.py's `companion_show_groups` says an empty `card_ids` list is legal and "the companion skips that group's **tiles**" — but GroupsView (per EXPERIENCE.md:94 and the 16.3 spec's own matrix: "Group skipped entirely — title and rationale included") skips the **whole group**. An agent pushing a prose-only group trusting the docstring has its heading and rationale silently vanish. The render side is artefact-backed; the docstring is the wrong side. **Disposition: fix now** (one-line reword + plugin rebuild).

**R3 — CONFIRMED: a widened outcome vocabulary crashes all four push tools.** `_execute_push` indexes `messages[outcome.outcome]` (companion.py:555); the tables carry exactly the four failure keys. A fifth failure token added to `PushOutcomeToken` in `client.py` raises `KeyError` inside the function whose docstring promises "never raises", and no test ties the table keys to the client's vocabulary. Nothing shipped today triggers it. **Disposition: defer (small guard)** — `assert set(_push_messages("x")) == set(get_args(PushOutcomeToken)) - {"displayed"}`.

**R4 — CONFIRMED (adversarial + verification-gap convergent): stale guard-coverage claim on the 16.2/16.3 seam.** `_PUSH_MESSAGES`'s docstring (companion.py:311, mirrored in plugin/) still says `TestEveryPushToolSpeaksItsOwnNoun` "reads all three tables by name"; 16.3 made it four (test_companion_tool.py:1321-1327 reads all four). The guard itself is correct — only its description under-counts. **Disposition: fix now (trivial, fold into R2's cleanup).**

**R5 — CONFIRMED: the 64 KB envelope warning is groups-only, but the hazard is not.** Same fact as A5(b), sharpened by arithmetic: a field-cap-maximal tier list (12 × 60 × 128-char ids + notes) ≈ 95–98 KB also exceeds the 64 KB envelope and comes back `payload_rejected`; only `companion_show_groups`'s docstring warns. The 16.3 session discovered the hazard and patched its own tool's doc. **Disposition: fix now (fold into R2's cleanup)** — state the envelope cap in the tier-list (and arguably swaps) docstrings.

**R6 — CONFIRMED: one-directional sibling-channel guards.** The swaps delivery test (socket.test.ts, "DELIVERS a `swaps` push") asserts `pushes`/`events` empty but not `tierPushes`/`groupsPushes`; the tier test asserts `swapsPushes` empty but not `groupsPushes` — each story's test pins silence only for the channels that existed when it was written. A future dispatch fallthrough double-delivering an early kind to a later channel passes the suite. Related: `test_no_clients_connected_is_pushed_once_and_never_re_sent` exists for suggestions only (test_companion_tool.py:673; absent at :839/:1012/:1188). **Disposition: defer (small hardening, fold with R3).**
