## Intent

**Problem:** A c7-3 refetch is invisible (no "updating" signal on the header, so UX-DR35's shimmer AC is unmet), and worse, its completion **releases the user's pin on every same-deck refetch** — `deckMemory` compares boards by object reference, so any settle evicts a pin even when the pinned card is still in the deck, and would evict every pinned suggestion (the c6-7 Q7 debt R9 closed).

**Approach:** Expose a refetch-in-flight flag from the deck slice and render it as the deck-header updating treatment (static "Updating…" micro text under `prefers-reduced-motion`, per UX-DR42). Replace the reference-comparison eviction with the R9 membership-transition rule: at boards replacement, evict a pin only if its card was in the departing decklist AND is absent from the new one — falling back to the existing cold-open target resolution. Add the owed end-to-end tests: pinned suggestion survives a refetch; a DFC's back face survives the re-render.

## Boundaries & Constraints

**Always:** `useDeckStore` stays written only by `src/state/deck.ts` and `useInspectionStore` only by `src/state/inspection.ts` (`store-writes.test.ts`); `deck.ts` must never even NAME `useInspectionStore` (the two-armed regex detector) — eviction runs at the `CardDetail` boards-effect seam, not in `deck.ts`. The updating flag is a sibling key on the existing store (no new store) whose clear points are generation-guarded like every other settle. The shimmer covers BOTH the c7-3 single-request refetch and a full re-drive behind a still-settled deck (EXPERIENCE.md names reconnect explicitly). Membership is by `card_id` (printing uuid) over ALL THREE boards (commander ∪ mainboard ∪ sideboard — a sideboard card is pinnable via `DeckList` and is "in the deck's list"); fallback target stays `coldOpenTargetOf` (grid order, sideboard excluded). Transient-target clearing on boards replacement is status quo (ACs legislate only the pin). Motion constraints are hard gates: nothing loops or pulses at any setting (stylelint), durations only via `--motion-*` tokens, reduced-motion handled ONLY in `tokens.css`'s media block, no new design token (the count is pinned at 70). "Updating…" is authored copy (copy-rules gate) spelled with `…`, `aria-hidden="true"`, no role, no `aria-live` (announcements are c7-5's; the live-region census is pinned). All firing proofs run through `scripts/vitest_probe_harness` (warm control first). Runtime `ui/` diff → rebuild `src/companion/app/static/` and `plugin/`, commit both.

**Block If:** The shimmer cannot be expressed within the no-loop/no-pulse stylelint gates without a new token or a DESIGN.md amendment (moving the 70-token pin is a human call); the R9 membership rule contradicts an existing AC that cannot be honestly amended beyond the tests named in the Code Map; the reduced-motion text swap cannot live in `tokens.css`'s media block without breaking its structural assertions in `token-usage.test.ts`.

**Never:** No announcements, live regions, or quantity-badge glow (c7-5); no deletion-UX or agent-view-interaction changes (c7-6) — today's 404-clear and view-behind-refetch behavior stay untouched. No timers anywhere (`deck.ts` timer ban; also no minimum-display-time for the shimmer). No pin-time classification of what a pin points at (the R9 rule reads only the two decklists at completion). No `faces.ts` behavior change (flip state already survives by construction — this story adds the missing end-to-end test only). No backend or wire changes. No new store, no second network door, no `deck.ts` import of inspection machinery. Do not wrap or replace the `<h1>` (focus-restore target; "exactly one h1" is pinned), and give the updating element no `role`/`region` semantics (AppShell role census is pinned).

## Design Notes

- **Why the flag lives in the deck store and the eviction does NOT live in deck.ts:** `store-writes.test.ts`'s detector is two-armed — if `deck.ts` merely names `useInspectionStore` the writer scan goes red. The boards effect in `CardDetail` already runs exactly once per settled boards reference and `deckMemory` already holds the departing boards, so the eviction needs no deck.ts edit at all. The updating flag, conversely, is deck-lifecycle truth only `deck.ts` can know.
- **Why the shimmer covers re-drives too:** EXPERIENCE.md's refetch rule opens "on `deck_changed` matching the active deck (and on WS reconnect)" — the reconnect re-drive is a two-request sequence behind a still-rendered deck (`App.test.tsx:2446` proves the heading stays). Gating the marker on `deck !== null && updating` gives cold boot no marker for free.
- **Why membership includes the sideboard but the fallback target excludes it:** a sideboard card is pinnable (DeckList rows) and is "in the deck's list" (R9's words); evicting it when it leaves is the rule working. The fallback reuses `coldOpenTargetOf`, which deliberately draws what the grid draws (commander first, no sideboard) — cross-checked against `CardGrid` by an existing test, and "first card of the first type group" in the epic AC describes exactly that resolution.
- **Why a card in BOTH decks now survives a deck SWITCH:** the R9 rule reads only the two decklists — "no pin-time classification" forbids asking how the boards came to change. c6-3's switch test used a card absent from deck B, so it pins nothing to the contrary; a pin surviving onto a deck that also contains the card is the rule composing, not a regression.
- **Why the transient-clear stays on every replacement:** the ACs and R9 legislate pins only; hover/focus are ephemeral by contract and their clear on replacement is shipped behavior no ruling overturns. Noted for c7-5+ if a real annoyance emerges.
- **Ellipsis ruling:** c5-7 banned "Reconnecting…" because the pill is a STEADY state and a trailing ellipsis promises the animation the repo bans. "Updating…" marks a bounded in-flight window that provably ends (the flag's clear points), and both the epic AC and the DR-42 inventory spell it with the ellipsis verbatim (UX-DR33: ship specified copy verbatim). Recorded here so the copy gate's precedent stays coherent.
- **Shimmer shape guidance (not a mandate):** a non-animated veil — e.g. dimmed identity block via `transition: opacity var(--motion-glide)` — persists honestly for the whole window, needs no `@keyframes` (whose rules the reduced-motion CSS reader cannot neutralize — `AgentView.tsx:148-156`), no `transform` (5-entry pin stays), and no new token. A one-shot sweep re-armed by the attribute flip is also legal (`animation-iteration-count: 1`). Anything looping is unimplementable — stylelint, not taste.
- Known flake context: the Python-side deck-repository flake family was fixed on master by R3 (PR #77, merged into this umbrella at `f0fe419`); a red there is NEW information, not the old noise. Frontend cold-run eslint timeout: run the harness control warm.
