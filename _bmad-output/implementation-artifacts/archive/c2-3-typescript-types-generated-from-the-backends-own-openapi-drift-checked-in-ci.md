# Story C2.3: TypeScript types generated from the backend's own OpenAPI, drift-checked in CI

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a developer on either side of the wire,
I want the UI's types generated from the backend's OpenAPI output and checked in CI,
so that a Python schema change cannot silently diverge from the TypeScript that consumes it.

**What this story really is.** It closes AD-12: `src/companion/contracts.py` becomes the single
source of truth for every shape that crosses the wire, and the TypeScript half stops being a thing
anyone can hand-write. Three stories have already been built *for* this one — c1-4 declared the
typed error contract app-wide precisely so `ErrorResponse` reaches `components.schemas`, c1-2's
`_CompanionFastAPI.openapi()` strips the auto-422 so a shape the API never emits cannot reach the
generated file, and c2-1 installed `openapi-typescript` unwired (Ruling B2) so the lockfile already
sits on `typescript@5.9.3`. Nothing is missing except the wiring and the gate.

It is a **small diff whose whole value is the gate**, so a vacuous gate is the only real failure
mode here. Two things must be true and both must be proven by breaking them: a Pydantic change with
no regeneration must be red, and a regenerated schema with stale TypeScript must be red.

**Five things were measured on this machine at the baseline commit (`9b612eb` — openapi-typescript
7.13.0, fastapi 0.140.0, prettier 3.9.x, node 24.15.0 local / 20 in CI). Do not rediscover them:**

1. **CI cannot run this pipeline in one job as the workflow stands.** `quality` has uv and the
   project's Python dependencies and **no Node**; `frontend` has Node and `npm ci` and **no Python
   dependencies** (`uv sync` never runs there). Producing `app.openapi()` needs the first;
   running `openapi-typescript` needs the second. The drift check therefore **splits by toolchain**,
   with the schema as a committed hand-off artifact — Decide-once #1, and Q2 is where to overrule it.

2. **Prettier would reformat the generated file, and c2-1 already knew.** `ui/.prettierignore` lines
   9-11 carry `src/api/types.d.ts` with the comment *"Generated by c2-3 … formatting it here would
   fight the generator"*. Measured: with the ignore path disabled, `prettier --check
   src/api/types.d.ts` reports *"Code style issues found"* (the generator emits 4-space indent and a
   152-char union line; `printWidth` here is 100). That entry is **load-bearing** — its comment says
   "Does not exist yet", which stops being true in this story. Update the comment; never delete the
   line, and never add a prettier pass to the generation script.

3. **Python's `json.dumps(indent=2)` is not prettier-clean either.** Prettier collapses short arrays
   (`"required": [\n "reason"\n ]` → `"required": ["reason"]`), 7059 → 7009 bytes. So the committed
   `openapi.json` needs its **own** `.prettierignore` line, for the same reason and beside the
   existing one.

4. **The whole Python docstring lands in the generated TypeScript as JSDoc — `Args:`, `Attributes:`,
   doctests and all.** FastAPI uses a route docstring as the operation `description` and a Pydantic
   class docstring as the schema `description`; `openapi-typescript` emits both as `@description`
   blocks. Measured today, for *one* endpoint and *two* models: **186 generated lines, ~130 of them
   prose**, including `Args:\n    request: The incoming request, used only to reach
   app.state.instance_id` and `>>> ErrorResponse(reason="deck_not_found").model_dump()`. Q1 rules on
   it; AC 17 is the fix if Q1 is accepted.

5. **`expectTypeOf` assertions are erased at runtime — a green vitest run proves nothing about
   them.** Measured: mutate the generated `status: "ok"` to `status: string` and `npm test` still
   passes 2/2 while `tsc -b` exits **2** with
   `error TS2344: Type '{ status: "ok"; … }' does not satisfy the constraint '{ status: "Expected:
   literal string: ok, Actual: string"; … }'`. The type gate is `npm run typecheck`. Say so in a
   comment, or a later author will "simplify" the assertions into a runtime test and silently delete
   the only thing that makes the generated types load-bearing.

**Four risks were measured and are now dead, so no one needs to worry about them:**

- The schema is **byte-identical on CPython 3.12.13 and 3.13.13** (measured with a separate
  `UV_PROJECT_ENVIRONMENT` + `uv sync --locked --python 3.13`), so the `quality` matrix cannot fight
  itself over the committed snapshot.
- `openapi-typescript` reruns on the same input are **byte-identical**, and its banner carries no
  version string — a patch bump churns the file only if the output genuinely changes.
- The generated `.d.ts` **is** linted (it matches eslint's `**/*.{ts,tsx}` block) and reports **0
  problems**; it is inside `tsconfig.app.json` via `include: ["src"]`, so `projectService` is happy
  and `tsc -b` is clean. No config change is needed to admit it.
- The generator writes LF and ends with a trailing newline; `ui/.gitattributes` (`* text=auto
  eol=lf`) covers both new files, so the drift check compares one deterministic byte sequence on
  Windows and ubuntu alike — the exact hazard that cost c2-2 a second `.gitattributes` line.

**What this story does not do.** It adds **no route, no model and no endpoint** — `/agent/events`
and its envelope union are c5-1/c5-5, `/api/decks` is c3-1, and a dummy endpoint is explicitly
banned by the epic. It adds **no runtime fetch layer** (c3-1 consumes, c4-1 owns the store), no
visual work, and no dependency on either side.

### The pipeline

1. **[epic] `ui/src/api/types.d.ts` is generated by `openapi-typescript` from the backend's own
   `app.openapi()` output, and it is committed.** Verbatim generator output: no hand edits, no
   formatting pass, no post-processing step. Flags stay **minimal** (`-o` and nothing else) — every
   flag is a permanent churn source in a drift-checked file, so adding one later needs a comment
   giving its reason.

2. **The schema hand-off is a committed `ui/src/api/openapi.json`, written by
   `scripts/dump_openapi.py`** and run as `uv run python -m scripts.dump_openapi`. Four
   requirements, each with a reason:
   - the output path resolves from `Path(__file__).resolve().parent.parent` (the `build_plugin.py`
     `REPO_ROOT` idiom), **never** from the cwd — c2-2's one self-inflicted vacuity was a stray
     `Set-Location` that planted a proof file in a directory nothing reads, and it nearly shipped
     inside an AC proof;
   - the bytes are `json.dumps(schema, indent=2, ensure_ascii=False)` plus exactly one trailing
     newline, written with `newline="\n"` — the snapshot test in AC 5 compares bytes, and an
     `os.linesep` write would be red on Windows and green on CI from the same commit;
   - project conventions apply because it is Python: module docstring with a `Usage:` block (the
     `build_plugin.py` shape), Google-style docstrings, `logger` not `print`;
   - the rendering is a **function** the test can import (e.g. `render_schema() -> str`), not inline
     code inside `main()`, so the test cannot drift from the writer.

3. **`src/api/openapi.json` is added to `ui/.prettierignore`,** beside the existing
   `src/api/types.d.ts` entry, with the measured reason (landmine #3). The existing entry's
   "Does not exist yet" comment is updated to describe what now exists and which command regenerates
   it. **Neither line is removed.**

4. **Two npm scripts, one documented workflow.**
   - `gen:types` → `openapi-typescript src/api/openapi.json -o src/api/types.d.ts`. This is the Node
     half, and it is the *exact* command CI runs — CI must not carry its own copy of the invocation.
   - `gen:api` → `cd .. && uv run python -m scripts.dump_openapi && npm run gen:types`. The one
     command a developer runs after touching a Pydantic model. `cd ..`, **not**
     `uv run --project ..`: `python -m scripts.…` resolves the `scripts` package from the cwd, so
     `--project` alone would fail to import it.

### Drift, both halves

5. **The Python half is a pytest snapshot test:** the committed `ui/src/api/openapi.json` bytes equal
   what `dump_openapi` renders from a live `build_app()`, and the failure message names
   `uv run python -m scripts.dump_openapi` as the fix. Import the renderer from the script —
   `tests/integration/test_build_plugin.py` is the precedent for a test importing `scripts.*`.

   > **Deliberate deviation from the epic's letter, flagged not silently taken** (the c1-9 / c2-1 /
   > c2-2 precedent). The epic says "CI regenerates and fails on `git diff --exit-code`". This is a
   > test rather than a workflow step because: it runs inside a gate that already exists, on **both**
   > matrix Pythons; it runs locally for every developer with no CI round trip; and its failure can
   > *name the fix*, where a `git diff` step can only say that something differs. Coverage is
   > identical — the test renders from the live app in CI, which is what regenerating does. Record it
   > in the Completion Notes.

6. **[epic] The Node half is a CI step in the `frontend` job:** after `npm ci`, run `npm run
   gen:types`, then fail on drift with an `::error::` annotation naming the fix. Copy the shape of
   the `SPA bundle in sync with ui/` step c2-2 shipped in the same job, including its **`git ls-files`
   non-vacuity guard** — `git status --porcelain` reports nothing for a gitignored or never-committed
   path, so without the guard a missing `types.d.ts` passes vacuously. Watch the working directory:
   the job sets `defaults.run.working-directory: ui`, so generation runs there while the git check
   needs repo-root-relative pathspecs (`working-directory: .`, or `ui/src/api/...` paths). Prove it
   is not vacuous.

   > `git status --porcelain` again rather than the epic's `git diff --exit-code`. Here the path is
   > stable, so `git diff` would mostly work — porcelain is chosen for consistency with the two
   > drift checks already in this workflow and because it also catches the untracked and
   > newly-ignored cases the guard above is about.

7. **Both halves are proven to have teeth, and both proofs are pasted.**
   - Add or rename a field on a companion Pydantic model, do **not** regenerate → the AC 5 test is
     red, with its instructive message. Regenerate → green.
   - Regenerate `openapi.json` only, leaving `types.d.ts` stale → the AC 6 command is red locally.
     Run `npm run gen:types` → green.
   - Revert both mutations and confirm the tree is clean. (Same discipline as c2-2's AC 13 and
     c2-1's deliberate mypy break.)

### The types are load-bearing — the non-vacuity of the whole pipeline

8. **[epic] `ui/src/api/schema.ts` is the one module that reads the generated file,** re-exporting
   narrow aliases (`HealthResponse`, `ErrorResponse`, `ErrorReason`) for the rest of `ui/src`.
   `import type` only: `verbatimModuleSyntax` is on and nothing about the generated file may reach
   the runtime bundle. This is also what gives c2-9, c3-1 and c4-1 one import to reach for instead of
   five different paths into a 1,000-line generated file.

9. **The pinned shapes are enforced by `tsc -b`, not by vitest.** `ui/src/api/schema.test.ts`
   asserts `HealthResponse` equals `{ status: 'ok'; instance_id: string }` and `ErrorReason` equals
   the six-token union (`deck_not_found`, `database_not_initialized`, `database_unavailable`,
   `invalid_request`, `payload_too_large`, `internal_error`). A comment must state that
   `expectTypeOf` is erased at runtime, so `npm test` passing means nothing here and `npm run
   typecheck` is the gate (landmine #5). Without this AC, a regeneration that emitted an empty file
   would pass every gate the project has.

10. **[epic] The UI never re-declares a shape the backend already describes — enforced, not
    documented.** A guard test reads the `components.schemas` keys out of the committed
    `openapi.json` and fails if any tracked file under `ui/src` **outside `src/api/`** declares
    `interface <Name>` or `type <Name> =` for one of those names. Non-vacuity pair: assert the key
    list is non-empty and contains `HealthResponse`, so a wrong path cannot make the ban pass by
    finding nothing (the `package-contract.test.ts` idiom). The rule grows on its own as c3-1 and
    c5-1 add models — which is the point.

11. **[epic] Exactly one generator, and a second one cannot arrive quietly.** Extend
    `ui/tests/package-contract.test.ts`'s ban list with the codegen alternatives —
    `swagger-typescript-api`, `@hey-api/openapi-ts`, `orval`, `oazapfts`, `openapi-zod-client`,
    `@openapitools/openapi-generator-cli`. **The epic's fifth block — `openapi-typescript` is
    dev/CI-only — is already satisfied** by that file's existing assertion (c2-1, Ruling B2, lines
    59-62): re-verify it passes and do **not** write a second copy of it.

12. **[epic] No dummy endpoint exists, and the mechanism that makes one unnecessary is written down
    where c5-1 will read it.** `POST /agent/events` will declare the envelope union as its request
    body, so the WebSocket types land in `components.schemas` from the route itself — one generator,
    both halves. Record that in `scripts/dump_openapi.py`'s docstring and/or `ui/README.md` with a
    **c5-1** key, plus a note that new routes and models appear in the generated file automatically
    (**c3-1** is the first). This story adds no route, model or endpoint of its own.

## Dev Notes

### Decide-once rulings (c3-1, c5-1, c5-5 and every later wire story inherit these)

**#1 — the drift check splits by toolchain, and the schema is a committed hand-off artifact.**
`quality` has Python and no Node; `frontend` has Node and no Python dependencies. So:

```
contracts.py ──(uv, quality job)──> ui/src/api/openapi.json ──(npm, frontend job)──> types.d.ts
             pytest snapshot test                            CI git-status drift check
```

Both files are committed and both halves are gated, so the chain from a Pydantic field to a
TypeScript property has no unguarded link: a model change with no regeneration reddens pytest, and a
regenerated schema with stale TypeScript reddens the frontend job. The alternative — one artifact,
one check, and `astral-sh/setup-uv` + `uv sync --locked` added to the `frontend` job — is Q2. Two
options were considered and rejected outright: `npx openapi-typescript@…` inside the `quality` job
(the runner does ship Node, but that bypasses the committed lockfile, which `npm ci` exists to make
canonical), and passing the schema between jobs as an upload/download artifact (cross-job ordering
and CI machinery to avoid committing a 7 KB file that is genuinely useful to read in a PR diff).

**#2 — the generated file is read through exactly one module.** `ui/src/api/schema.ts` owns every
import of `./types`; the rest of `ui/src` imports named aliases from it. A component reaching into
`paths['/api/deck/{id}']['get']['responses'][200]…` for itself is how five spellings of the same
type appear across four stories. Add the alias, then use the alias.

**#3 — the generator's flags are part of the committed contract.** `-o` and nothing else today.
Any flag added later rewrites the whole file, so it arrives with a comment saying why, in the same
commit as the regenerated output.

**#4 — a new endpoint or model needs no pipeline work.** Write the route with a `response_model` and
`error_responses(...)`, run `npm run gen:api`, commit both generated files. That is the entire
c3-1 / c3-2 / c5-1 / c5-5 obligation, and the two gates are what make forgetting it loud.

**#5 — (Q1) descriptions are summaries, not docstrings.** If accepted: everything from the first
Google-style section header onward is Python's business and stops at the schema boundary. Write
route and model docstrings normally; the first paragraph or two is what the frontend and `/docs` see.

### Architecture rules this story implements

- **AD-12** in full: *"Contracts are Pydantic models in `src/companion/contracts.py`. TS types are
  generated by `openapi-typescript` from the backend's own `app.openapi()` output into a committed
  `.d.ts`, and CI regenerates and runs `git diff --exit-code` … One generator covers both halves,

### Gotchas specific to this story

1. **Two generated files, one truth, and they must be committed together.** A commit carrying a
   fresh `openapi.json` and a stale `types.d.ts` is red in CI, and a bisect that lands on it has a
   broken frontend gate for reasons unrelated to what is being bisected. Regenerate both, commit
   both, in the commit that changes the model.

2. **`prettier --check` on an ignored path is silently vacuous.** Naming the file explicitly does
   *not* override `.prettierignore` — measured: `prettier --check src/api/types.d.ts` prints
   *"All matched files use Prettier code style!"* while matching nothing. So do not use that command
   as evidence of anything about the generated files; use `--ignore-path` pointed at a nonexistent
   file when you want to see what prettier *would* do.

3. **`info.version` is FastAPI's default `0.1.0`, not the package version.** Leave it. Wiring it to
   `__version__` would make every release bump churn the committed schema *and* the generated types
   for no wire change — a c8-4 decision at best, with that cost stated.

4. **The generated file is 4-space-indented and long-lined on purpose.** It is the generator's
   output, not this project's style. Nobody's editor should reformat it, and the `.prettierignore`
   entry plus the `@generated`-style banner are what say so.

5. **`npm run build` mutates `src/companion/app/static/` (c2-2).** Nothing in this story needs a
   build, but the fifth gate runs one. Check `git status` before committing so a rebuilt bundle does
   not ride along in a types commit.

6. **Node 24 locally, node 20 in CI.** `openapi-typescript` is a pure TypeScript printer and its
   output should be version-independent, but "should" is doing work — the same shape of risk c2-2
   carried for the Vite bundle. **Push early and let CI speak.** If CI reports drift on an otherwise
   unmodified tree, that is a finding to record and raise, **not** a reason to loosen the check.
   Preference order: identify and pin the varying input; normalise the compared surface while keeping
   it a hard gate; escalate to Brad. Do not make the check advisory.

7. **Do not let the guard test in AC 10 become a grep for arbitrary strings.** Its authority comes
   from reading `components.schemas` out of the committed schema. If it ever hard-codes a name list,
   it stops growing with c3-1 and c5-1 and becomes decoration.

8. **`scripts/` is not type-checked.** `mypy src/` in CI and `files: ^src/` in pre-commit both stop
   at `src/`. `ruff` does lint `scripts/`. So keep `dump_openapi.py` thin and let the AC 5 snapshot
   test be its real coverage — the same bargain `build_plugin.py` already lives under.

9. **A pytest test must not shell out to `npm`, and a vitest test must not shell out to `uv`.**
   Either would need the other toolchain at test time and contradict AD-13. The split works precisely
   because the pytest side builds the app (no Node) and the vitest side reads a committed JSON file
   (no Python).

model will redden CI until both artifacts are regenerated. Proposed (AC 17): truncate each

*Alternatives:* accept the docstrings verbatim (zero `src/` change, and the generated file carries
Python's `Args:` and doctests forever); or strip descriptions entirely (smallest, most stable
artifact, but throws away documentation the frontend genuinely wants on hover).
**Recommend: truncate, as proposed.**

**Q2 — the split drift check and the committed `openapi.json` (Decide-once #1).** `quality` has no

two, at the cost of a third Python environment install in CI and a `ui` npm script that shells into
uv on the CI path as well as locally. **Recommend: as proposed.**
